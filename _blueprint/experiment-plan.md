# GEVIS 현재 방향과 다음 검증

기준: 2026-10-23 · Direction D0011 · `decision_system=fusion_answers`

## 1. 목표와 현재 구현

**학습된 모델이 PECVD·PEALD 새 입력의 변화 유무·유형·강도를 정확하고 빠르게 반환하는 것**이 목표입니다. BOOLEAN·CHOICE·ORDINAL 모두 Fast 출력입니다. Precision은 미래 연속값 예측으로 별도 정의합니다.

```text
입력 창 → 고정 TRAIN 정규화·참조 → 인코더·질문 Fusion → 학습 헤드 → 세 답변
```

PECVD는 Step별 인코더와 공통 Fusion을 사용합니다. PEALD 기본은 **PECVD DEP 인코더·Fusion 동결 + PEALD 공통/채택된 Step 헤드**입니다. PEALD Step마다 PECVD source 인코더를 자동 교체하는 설정이 아닙니다. 학습은 TRAIN, 선택은 Validation, Test는 평가입니다.

**폐기한 접근:** 10월21~22일 검토한 통계 threshold·분위수 조정으로 최종 답을 정하는 방식은 룰베이스와의 차이가 부족하다는 판단으로 채택하지 않았습니다. 10월22일 폐기 결정으로 기록하며, 현행은 학습 헤드의 답변입니다. auto labeling을 통해 학습할 정답을 준비하는 다음 실험과 이 폐기한 최종 판정 방식을 구분합니다.

## 3. 성능과 시간의 판단 기준

- Fast 목표: 세 답변 요청 평균≤50ms, F1≥0.96. BOOLEAN 양성 F1, CHOICE/ORDINAL macro F1·변화 사례 정확도·강도 오차를 분리 보고합니다. 답변별 최종 수락 기준은 미확정입니다.
- 합성 paired 점수는 알려진 변형 정답을 맞힌 결과입니다. 실제 정상/고장 판별 성능은 별도 정답이 필요합니다. 과거 Test 참고 이력이 있어 현재 Test를 최종 미열람 holdout으로 선언하지 않습니다.
- 요청 시간은 참조 선택·정규화·인코더·Fusion·헤드·결과 구성입니다. 수집·파일 읽기·창 준비·큐·전송을 포함한 물리cycle/Edge KPI와 구분합니다.
- 새 입력에는 정답 없이 예측할 수 있습니다. 그 예측이 맞는지 채점하려면 독립 정답이 필요합니다. 외부 채점을 끈 것이 기존 경보 문제의 해결을 뜻하지 않습니다.

## 4. 향후 방향 — 우선 실험할 세 가지

아래는 **다음 실험 계획**입니다. 현재 코드에 auto labeling 학습·깊은 추론·통일된 seed/속도 측정 설정이 모두 적용됐다는 뜻은 아닙니다.

### 4.1 Auto labeling으로 정답을 준비해 GEVIS 이상 탐지 학습

**auto labeling으로 정상/이상 후보 정답이 붙은 데이터를 준비하고, 그 데이터로 GEVIS를 학습했을 때 실제로 이상 탐지가 되는지 확인합니다.** 현재 합성 변화 판독 성능을 이 실험의 완료 결과로 사용하지 않습니다.

1. 라벨의 의미를 정합니다. 현재의 변화 있음/없음과 공정 정상/이상은 다르므로, 어느 현상을 이상으로 볼지와 센서·구간·유형·강도 기준을 정합니다.
2. 원본 회차를 TRAIN/Validation/Test로 먼저 나눕니다. auto labeling 학습·보정이 필요하면 TRAIN에서만 수행하고, 생성 방법·버전·불확실/미라벨 사례를 함께 기록합니다. 정답을 가진 외부 데이터도 이 규약에 맞춰 연결합니다.
3. 자동 생성 정답을 검토·확정한 데이터로 GEVIS 학습 실험을 구성합니다. 우선 답변 헤드 학습 범위를 정하고 인코더·Fusion 추가 학습 여부는 별도 비교로 결정합니다. 기존 모델은 대조군으로 보존합니다.
4. 모델은 Validation에서 선택하고 독립 Test에서 정상/이상 탐지 F1·재현율·오탐률을 평가합니다. 유형·강도 정답이 있는 경우 CHOICE·ORDINAL도 함께 평가합니다.

자동 생성 라벨만 그대로 재현한 점수와 전문가 검토·독립 정답에 대한 점수를 나누어 보고합니다. 자동 라벨이 통계 규칙에서 왔다면 그 규칙의 재현만으로 실제 이상 탐지 성공이라고 결론 내리지 않습니다. Test 정답은 학습·모델 선택에 사용하지 않습니다.

### 4.2 깊은 추론이 필요한 경우의 별도 처리 설계

빠른 유무·유형·강도 판단만으로 설명하기 어려운 복합 변화, 여러 센서·Step의 관계, 원인 후보나 후속 조치 검토가 필요한 사례를 모읍니다. **GEVIS의 빠른 판단을 유지하면서 어떤 경우에 추가 추론을 요청할지** 설계·비교합니다.

추가 경로에 전달할 파형 요약·선택 센서·참조·모델 답변과, 필요한 결과·응답시간·평가 정답을 정합니다. 더 큰 모델이나 별도 추론 모델은 후보이며 아직 선택하지 않았습니다. 설명의 근거 일치·유용성·지연·비용을 평가하고, 실제 고장 원인을 단정하지 않습니다.

CHOICE·ORDINAL은 계속 Fast 출력입니다. 이 추가 추론 경로를 미래 연속값 예측 과제인 Precision과 동일시하지 않습니다. 호출 정책과 실행 순서는 후속 실험에서 결정합니다.

### 4.3 Seed와 입력·환경을 고정한 성능·속도 재현 실험

실행마다 처리 시간이 달라지는 이유를 확인하려면 **seed와 측정 조건을 함께 고정**해야 합니다. 비교 기준 seed는 기존 설정과 맞춘42로 제안하며, Python·NumPy·PyTorch 및 해당 시 CUDA/DataLoader의 난수 설정 적용 여부를 점검합니다. seed·분할·샘플 선택·주입 조건·입력 순서를 기록하고 비교 모델이 같은 창을 처리하게 합니다.

같은 체크포인트·참조·센서 수·창 길이·질문 수·batch 크기를 사용합니다. 장비·라이브러리·CPU thread 설정·동시 작업 조건을 기록하고 워밍업 횟수와 반복 횟수, GPU 동기화·측정 경계를 맞춥니다. 첫 요청과 워밍업 이후를 분리해 평균·중앙값·p95/p99·실행 간 변동을 보고합니다.

**Seed 고정은 동일 입력과 난수 조건의 재현을 돕지만 처리시간을 매번 같은 값으로 만들지는 않습니다.** 장비 부하·캐시·GPU/CPU 실행 상태 등의 변동은 반복 측정으로 확인합니다. 결정적 연산 옵션이 필요한 경우 출력 재현성과 속도 영향을 함께 비교하며, 시간 차이의 원인을 seed 하나로 확정하지 않습니다.
