## 평가에서 유지하는 조건

- 학습·정규화는 TRAIN, 모델 선택은 Validation, Test는 평가에 사용합니다. 기존 Test 결과를 참고한 개발 이력이 있어 최종 미열람 holdout 성능과 구분합니다.
- 합성 변화의 정답은 실제 정상/고장 정답과 다릅니다. 새 입력 예측의 정확도 검증에는 별도 정답이 필요합니다.
- Feature ablation은 같은 예제에서 헤드 입력 정보를 제한하고 임시 헤드를 재학습합니다. 구성요소를 실제 제거한 속도 실험은 아닙니다.
- 모델 창 요청 지연과 수집·큐·전송을 포함한 Edge 전체 지연을 구분합니다. 세 답변을 모두 평가합니다.

## 다음 실험 방향

1. **Auto labeling 정답으로 GEVIS 학습:** 라벨이 있는 데이터를 준비·검토하고 학습 후 독립 Test에서 정상/이상 탐지가 되는지 확인합니다. 자동 정답을 재현하는 점수와 실제 이상 탐지 성능은 구분합니다.
2. **깊은 추론의 추가 처리:** 빠른 판단으로 부족한 복합 변화·원인 후보·후속 조치 검토에 어떤 추가 추론이 필요한지 설계합니다. CHOICE·ORDINAL은 Fast 출력으로 유지합니다.
3. **재현 가능한 속도 비교:** seed와 입력·장비·워밍업·반복 조건을 고정합니다. seed만으로 실행시간이 같아지는 것은 아니므로 평균·p95/p99·실행 간 변동을 함께 확인합니다.
