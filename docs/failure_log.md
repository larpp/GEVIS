# 시행착오와 수정 이력

## STEP 노트북 삭제와 복구

후속 수정에서 `notebooks/training/` 실행용 STEP 3·3.1을 현재 evaluate API와 저장 헤드 경로에 연결했습니다.
각 실행용 노트북의 첫 셀은 공통 경로 설정을 사용합니다. STEP 1·2는 저장본 재사용으로 전체 셀 실행,
STEP 3은 현재 CVD/ALD 헤드 로딩, STEP 3.1은 네 헤드의 인공 입력 추론 연결을 확인했습니다.
STEP 1의 학습 이력 그래프는 현재 환경의 matplotlib DLL 오류 때문에 SVG 표시로 변경했습니다.
원본 노트북·현재 evaluate·가중치는 보존했으며 재학습은 하지 않았습니다.

미사용 파일 정리 범위를 잘못 판단해 개발용 STEP 노트북과 GEVIS_load를 삭제했습니다.
Git 커밋 기록만 확인해서 복구할 수 없다고 한 설명도 불충분했습니다. 이후 남은 Git 객체에서
STEP 1·3·3.1 원본을 찾았고, STEP 2는 인접 프로젝트의 원본 사본으로 복원했습니다.
GEVIS_load는 같은 작업 폴더 세션의 8개 셀 본문을 복구했으며 메타데이터는 재구성했습니다.
`notebooks/training/`에 개발용 실행 사본과 원본·복구 근거를 보존합니다. 준비 경로와 보조 모듈을
복구했으나 전체 재학습을 실행한 것은 아닙니다. 현재 ALD/CVD 노트북과 가중치는 변경하지 않았습니다.
이 자료는 보존 대상으로 분류하며, 배포본의 최소 구성 여부를 로컬 삭제 근거로 삼지 않습니다.

이 문서는 과거 시도에서 확인한 문제, 수정 이유, 검증 범위를 모은 기록입니다.
이전 `_docs`, `_blueprint`, `_note`에 흩어진 설명을 통합했습니다. 당시의 제안이나 개발용
평가 결과를 현재 모델의 검증된 성능으로 간주하지 않습니다.

## 정리·문서 작업에서 확인한 문제

- 배포본만 정리하고 로컬 캐시·이전 실험 폴더를 남겨 사용자의 실제 정리 요청을 충족하지 못했다.
  이후 명시적 삭제 요청에 따라 미사용 코드·구버전 가중치·캐시·보관 복사본을 실제 삭제했다.
  삭제 결과와 유지 자산은 [정리 결과](cleanup_candidates.md)에 기록한다.
- 이전 문서를 그대로 남겨 현재 동작과 과거 계획, 한국어와 영어가 섞였다. 현재 문서는 한국어로
  다시 정리하고 과거 설계 변경은 이 파일에 모은다.
- 설명용 합성 도식만으로 인코더 학습을 설명하기 부족했다. 저장된 공정별 학습 이력과
  검증·Test 복원 오차를 읽어 [실제 학습 기록](training/README.md)을 생성한다. 재학습이나
  예시 수치 생성은 하지 않는다.
- 기존 환경에서 matplotlib Agg 확장 DLL 로딩 오류를 확인했다. 운영용 Python 패키지는
  변경하지 않고 문서 렌더링용 임시 패키지에서 실제 기록 그림을 생성했다.
- 배포 코드와 비공개 자산이 같은 위치에 있다고 가정한 노트북 경로를 수정했다. `WORKSPACE_PATH`로
  자산 위치를 분리하고 CVD 복원 셀이 경로를 다시 덮어쓰지 않도록 했다. 실제 CVD·ALD 입력 준비를
  실행해 확인했으며 학습은 금지한 상태로 검사했다.
- Git의 자동 줄바꿈 변환이 소스 SHA256과 배포 파일 체크섬을 바꿀 수 있어 `.gitattributes`로
  원본 바이트를 보존한다. 기능이 같은 코드라도 바이트가 다르면 기존 저장 모델 검사가 실패할 수 있다.

## 해석에서 유지할 원칙

합성 변화 정답은 실제 설비 고장 정답이 아니다. 센서·Window 지표는 Run 전체 평가와 다르다.
기존 개발에서 Test 결과를 참고한 이력이 있으므로 모든 과거 수치를 최종 미열람 평가라고 부르지
않는다. 유형 혼동·다중 후보·보류를 구분하며 여러 Sigmoid 점수가 높다는 이유만으로 복합 고장을
확정하지 않는다. 성능 개선은 동일 조건의 별도 평가로 확인한다.
