# 판별 정답·헤드·평가와 시간 측정

기존 흐름의 한계는 전처리·특징 추출·판별 실험이 노트북 및 과거 실험 모듈에 얽혀 있었다는
점입니다. 핵심 특징 추출기를 분리해 새 후속 판별 과제를 추가할 때 내부 모델을 수정할 필요를 줄였습니다.
이번 작업에서 기준 모델의 파라미터·전처리·라벨 정책을 개선한 것으로 표현하지 않습니다.

학습 순서는 Run 분할 → TRAIN 정규화/정상 참조 → 연속값 합성 변화 → 고정 인코더·융합 →
판별 헤드 학습입니다. 검증 데이터로 학습 반복 시점을 선택하며 Test는 선택 이후 평가합니다.
TRAIN MIN/MAX 범위 밖의 관측은 변화 라벨 구성 근거이며 실제 고장 정답이 아닙니다.

| CHOICE | 의미 |
|---|---|
| Softmax | 양성 5유형 중 하나 |
| Grouped Softmax | 기본 (수준,기울기)/(변동성)/(국소)/(지연) 그룹 중 하나 |
| Sigmoid | 유형별 독립 점수 5개. 비교 F1은 최고 점수 유형을 사용하고 임계값을 넘은 후보는 별도 출력 |

현재 학습 정답은 단일 주입 유형입니다. Sigmoid 다중 후보를 복합 이상 검증으로 해석하지 않습니다.
현재 실험 규약은 `known_boundary_excess_all_splits_v6`입니다. ORDINAL은 실제 파형의 최대 경계
초과량을 `max(TRAIN 정상 범위 폭, TRAIN 정규화 1단위)`로 나눈 값으로 구성합니다.
목표 수준은 0.5·1·2·4이며 인접 목표의 기하평균으로 단계를 구분합니다. 지연도 실제 샘플 지연으로
만든 뒤 같은 초과량 척도로 확인하며, 도달할 수 없는 단계는 미지원입니다. 과거 진폭/지연 샘플 수
기반 단계와 다르며 물리적 불량 심각도를 뜻하지 않습니다.
합성 유형 도식은 [types.svg](injection_types/types.svg)이며 실제 측정 결과가 아닙니다.

평가에는 BOOLEAN F1, 정상 오탐 건수/분모, CHOICE 세부/공통그룹 F1, ORDINAL F1,
공정/센서별 분해, 지원/제외 Window 및 Run 비율을 함께 기록해야 합니다.
센서/Window 단위 성능을 Run 전체 판정이나 실제 설비 고장 검출 성능이라고 부르지 않습니다.

추론 지연은 모델 로딩·원본 CSV 준비·워밍업을 제외하고 GPU 동기화 전후 실제 경과 시간으로 측정합니다.
전체 센서에 대한 수치 특징 추출·융합·헤드·결과 변환을 포함하는 Window 단위 시간입니다.
BOOLEAN 양성 수에 따라 CHOICE/ORDINAL 추가 실행량이 달라질 수 있으므로 정상/합성 양성 입력,
Window 길이·센서 수·장치·반복 수·평균/중앙값/P95를 함께 명시합니다.
1초=1000ms. 0.50ms 목표와 0.50초 목표는 다릅니다.

기존 대화에서 얻은 성능 수치는 저장본·입력 명세를 함께 고정하지 못했으므로 새 공개 README의
검증된 성능 기준표로 옮기지 않았습니다. 증류는 이번 리팩터링 범위에 포함하지 않습니다.
