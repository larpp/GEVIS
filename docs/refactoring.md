# 구조 변경과 폴더 정리

## 현재 구조

Python 코드는 표준 `src` 구조로 모았습니다. `src/GEVIS_Model`은 공개 특징 추출 패키지,
`src/heads`는 CVD·ALD 응용, `src/pecvd`는 저장 모델을 지원하는 내부 호환 구현입니다.
패키지 이름과 공개 import는 유지합니다. 설치 경로만 프로젝트 루트에서 `src`로 바꿨습니다.
`notebooks`에는 ALD·CVD 평가를, `notebooks/training`에는 STEP 1·2·3·3.1과 GEVIS 로딩을 둡니다.
설정은 `config`로 통합하고, 기존 `configs` 예시는 `config/examples`로 옮겼습니다.
가중치 안내와 실패 이력은 각각 `docs/weights.md`, `docs/failure_log.md`에 있습니다.

이전 학습 노트북의 코드는 `src/heads/_legacy_training`에 Python 프로그램으로 옮겼습니다.
실행 시 과거 노트북을 읽지 않습니다. 새로운 데이터용 숫자 인코더 학습과 기존 전체 학습 과정은
서로 다른 진입점이며 [README](../README.md)에 구분했습니다.

## 기존 코드 일부가 남아 있는 이유

기존 헤드는 소스 파일의 해시와 실행 환경 식별자를 저장합니다. `src/pecvd`에서 보수적으로
확인한 모듈은 현재 저장 가중치의 로딩·전처리·헤드 학습과 기존 학습 프로그램의 의존성입니다.
필요하지 않은 모듈은 제거하고 이 호환 계층만 남깁니다. 모듈 안에 예전 비교용 함수가 일부
있을 수 있지만, 파일을 임의로 줄여 저장 모델의 호환성 검사를 깨뜨리지 않습니다.
독립 인코더 배포본에는 이 호환 계층을 포함하지 않습니다.

## 실제 삭제와 유지 항목

사용자의 미사용 파일 삭제 요청에 따라 과거 실험 캐시, 임시 환경, 보관 복사본, 구버전 가중치,
사용하지 않는 코드·시험·문서 폴더를 실제로 삭제합니다. 삭제 결과는 [정리 결과](cleanup_candidates.md)에
기록합니다. 이전 설계와 수정 이유는 [시행착오 기록](failure_log.md)으로 통합했습니다.

유지하는 항목은 원본 데이터, 현재 평가 노트북과 결과, 현재 6개 공정 인코더와 기존 CVD 입력 구간,
질문 인코더·융합 가중치, CVD·ALD 판별 헤드, 실행 코드·설정·문서·회귀 시험입니다.

유지 캐시는 `.cache/ald-native-inputs`와 `.cache/ald-experiment-features`입니다.
전자는 원본 센서 행렬의 디스크 저장소, 후자는 헤드 학습에 재사용하는 특징 저장소입니다.
보조 폴더를 지우는 작업과 원본 데이터·현재 모델을 지우는 작업을 구분합니다.

## GitLab 배포

배포본에는 원본 데이터·가중치·캐시·개인 설정·Git 이력을 넣지 않고 노트북 출력도 제거합니다.
로컬 노트북 출력과 복구한 원본은 보존합니다. 원격에는 검토한 소스 배포본을 정상 커밋으로 반영하며
기존 Git 이력을 강제로 재작성하지 않습니다. 배포 방식은 [README](../README.md)에 있습니다.

## 구조 이동 검증

이동 전후 내부 호환 소스와 현재 모델·입력 자산 103개 파일의 SHA256이 일치합니다.
학습 알고리즘이나 전처리를 바꾸지 않았습니다. 새 설치 경로에서 라이브러리 테스트 12개와
STEP 1·2의 저장본 재사용 실행, CVD·ALD 저장 헤드 추론 연결을 확인합니다.
